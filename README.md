# ReCall — 강의 PDF에서 개념별 복습까지

3개월 대학 진로 탐색 수업을 위한 **웹 전용 첫 MVP**입니다. React·TypeScript 클라이언트, Java 21·Spring Boot API, PostgreSQL·Flyway, PDFBox 텍스트 추출, 서버 측 Claude API를 사용합니다. 운영체제는 **실제 강의계획서로 검증하지 않은 임시 단일 과목**이며, 10개 고정 개념 태그만 허용합니다.

## 실행

### Docker Compose — 기본 PostgreSQL 구성

Docker Engine/Desktop와 Compose v2가 필요합니다.

```sh
cp .env.example .env
# .env의 POSTGRES_PASSWORD를 로컬 개발용 값으로 변경
docker compose up --build
```

- 웹: <http://localhost:5173>
- API 상태: <http://localhost:8080/actuator/health>
- 종료: `docker compose down` — DB 데이터는 `postgres-data` 볼륨에 유지됩니다.
- API 키는 **필수가 아닙니다**. 먼저 생성 화면의 **DEMO**를 사용하세요.
- `.env`는 Git에서 제외됩니다. 키를 채팅·클라이언트 코드·Git에 넣지 마세요.
- 웹/API는 호스트의 loopback에만 노출되고 DB 포트는 외부 공개하지 않습니다.

### Docker가 없는 경우 — 명시적인 로컬 H2 프로필

Java 21+, Node 22.12+가 필요합니다. Maven은 프로젝트 래퍼가 내려받습니다. 최초 빌드에는 패키지 저장소에 접속할 인터넷이 필요합니다.

```sh
# 터미널 1
cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

```sh
# 터미널 2, 저장소 루트에서
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

브라우저에서 <http://localhost:5173>을 엽니다. 로컬 프로필의 파일 DB는 재시작 후에도 유지됩니다. **H2는 개발용이며 PostgreSQL 동작 검증을 대체하지 않습니다.** 기본 설정은 PostgreSQL이고 연결 실패 시 H2로 자동 대체하지 않습니다. 로컬 실행은 루트 `.env`를 자동으로 읽지 않습니다. LIVE가 필요할 때만 해당 서버 프로세스 환경에 직접 설정하세요.

## DEMO와 LIVE

**DEMO**는 업로드 없이 실행하는 고정 운영체제 예제입니다. 업로드한 PDF에서 생성한 문제가 아니며, PDF 페이지 출처도 표시하지 않습니다. API 키나 외부 AI 호출 없이 문제 관리 → 퀴즈 → 결과·오답 → 복습 흐름을 탐색합니다.

**LIVE**는 사용자가 직접 서버에 `LIVE_ENABLED=true`, `CLAUDE_API_KEY`, `CLAUDE_MODEL`을 설정한 뒤 PDF를 선택하고 요청할 때만 Claude를 호출합니다. 기본 `LIVE_ENABLED=false`는 유료 호출을 막습니다. Compose에서는 로컬 `.env`에 값을 설정한 뒤 `docker compose up -d --build`로 서버를 재생성하세요. 로컬 Java 실행은 동일한 환경변수를 설정한 후 서버를 재시작해야 합니다. `.env.example`의 모델은 변경 가능합니다. 실제 API 모델 접근 권한과 [Anthropic 모델 목록](https://platform.claude.com/docs/en/models/overview)을 확인하세요. 업로드만으로는 AI를 호출하지 않습니다. 생성 시에는 추출된 강의 텍스트가 Anthropic에 전송되므로, 자료 사용 권한과 개인정보 포함 여부를 확인하세요. 실패를 DEMO로 바꾸거나 성공으로 가장하지 않습니다.

API 키·실제 강의 PDF·강의계획서가 제공되지 않았으므로 **실제 생성 품질·시간·비용을 측정한 결과는 없습니다**. 외부 모델을 사용한 검증은 자동 테스트에 포함하지 않습니다.

## 학습 규칙

| 상태 | 다음 상태와 복습일 |
|---|---|
| 아직 풀지 않음 | box 0, 복습 대상 아님 |
| 첫 풀이 정답 또는 오답 | **box 1, 내일** |
| 이후 정답 | 다음 box, 최대 5 |
| 오답 | box 1, 내일 |
| box 1 / 2 / 3 / 4 / 5 | 답변한 날짜부터 1 / 3 / 7 / 14 / 30일 |

날짜는 서버의 **Asia/Seoul 달력 날짜** 기준입니다. 오늘 복습에는 연체도 포함합니다. 모든 답변한 문제가 복습에 등록되므로, 첫날 18문제 중 6문제를 틀려도 **내일은 틀린 6개만이 아니라 답변한 18개가 대상**입니다. 기존의 “오답 6개만 다음 날 복습” 예시는 이 규칙과 다릅니다.

정확도는 현재 삭제되지 않은 문제의 모든 유효 답변 중 정답 비율이며, 같은 문제의 반복 풀이도 각각 셉니다. 오답 화면은 **최신 답변이 오답인 미해결 문제**이고, 이전에 틀렸다가 맞힌 문제는 빠집니다. 따라서 누적 정답률과 오답 목록의 의미가 다릅니다.

문제 편집은 버전을 올리고 해당 문제의 기존 답변·복습 상태를 초기화합니다. 이전 버전으로 답변하면 충돌 오류가 납니다. 삭제 문제는 퀴즈·복습·현재 통계에서 제외됩니다. 답변은 요청별 idempotency key로 재전송을 구분해 같은 요청으로 중복 승급하지 않습니다.

## PDF와 생성 작업

- 텍스트 PDF만 지원: 파일 최대 10MB, 최대 80페이지. 잘못된 파일, 암호화되어 읽을 수 없는 자료, 빈/스캔 자료는 명시적으로 거부합니다.
- 페이지 출처를 유지한 문자 예산 청크로 나눕니다. 빈 페이지마다 무조건 문제를 만들지 않습니다.
- 실제 페이지 범위와 허용 태그를 검증한 뒤 저장합니다. 출처 표시는 해당 입력 청크의 페이지 범위이며 **내용의 정답성까지 입증하는 인용 검증은 아닙니다**.
- 작업은 `202`와 ID를 반환한 후 폴링합니다. `queued → running → succeeded / partial / failed`로 진행합니다.
- 실행 동시성·대기열·재시도·출력 문항 수·응답 크기·요청 시간이 제한됩니다. 성공 청크는 부분 실패에도 보존합니다.
- 기본 한도는 작업 실행 2개·대기 8개, 청크당 최대 3회 시도·3문항, 작업당 최대 30문항입니다. 최종 문항 수는 자료와 검증 결과에 따라 달라집니다.
- 재시작 시 중단된 작업을 실패/부분 성공으로 정리합니다. 자동 무한 재개하지 않습니다. 큐 포화와 오류는 화면에 표시합니다.
- PDF 텍스트는 지시가 아닌 신뢰하지 않는 자료로 모델에 전달합니다. 출력은 문항, 서로 다른 보기 4개, 정답 인덱스, 허용 태그 하나, 난이도, 해설로 검증합니다.
- 요청 시간·파싱 시도/성공·제공되는 토큰 사용량을 남기되 키나 PDF 본문을 로그에 남기지 않습니다.
- 40페이지 지원은 설계 목표입니다. 모든 40페이지 PDF가 컨텍스트를 넘는다고 가정하지 않으며, “18문제/30초” 같은 보장을 하지 않습니다.

## API 요약

`POST /api/learners`로 발급한 익명 토큰을 브라우저가 보관하고 이후 `X-Learner-Token` 헤더로 전송합니다. 다른 학습자의 ID를 알아도 데이터를 조회·수정할 수 없게 서버에서 범위를 제한합니다. 오류 본문은 `{ "code": "...", "message": "..." }` 형태입니다.

| 경로 | 용도 |
|---|---|
| `POST /api/learners`, `GET /api/config` | 익명 학습자 발급, 실행 설정 |
| `GET /api/tags`, `GET /api/dashboard` | 고정 태그, 오늘 복습·개념 성적 |
| `GET/POST /api/documents` | PDF 목록·multipart `file` 업로드 |
| `GET/POST /api/jobs`, `GET /api/jobs/{id}` | 작업 생성·진행·청크 오류/지표 |
| `GET /api/questions?view=manage\|quiz\|due\|mistakes` | 문제 관리·퀴즈·복습·미해결 오답 |
| `GET/PUT/DELETE /api/questions/{id}` | 문제 조회·편집·삭제 |
| `POST /api/attempts` | 답변 저장 및 복습 상태 원자적 갱신 |
| `GET /actuator/health` | 상태 확인 |

LIVE 작업 요청은 `{ "mode": "LIVE", "documentId": "..." }`, DEMO는 `{ "mode": "DEMO" }`입니다. 퀴즈/복습 응답에는 제출 전 정답·해설이 없습니다. **관리 화면에서는 의도적으로 정답을 공개**하므로 시험 부정행위 방지 시스템이 아닙니다.

## 검증

```sh
cd backend && ./mvnw test
cd ../frontend && npm ci && npm test && npm run build
cd ..
# 백엔드를 별도로 실행한 상태에서, localhost에만 테스트 데이터를 만듦
python3 scripts/smoke.py
# 프런트엔드/백엔드가 실행 중일 때 실제 Chromium UI 검증
cd frontend
npm run test:e2e:install
npm run test:e2e
```

HTTP smoke는 작은 자체 제작 텍스트 PDF를 올리고, 잘못된 PDF 거부, 비동기 DEMO, 학습자 격리, 제출 전 정답 비공개, 답변·재전송, 서울 기준 내일 일정, 오답, 편집 무효화, 삭제를 검사합니다. LIVE 요청은 하지 않습니다. 테스트용 익명 학습자와 업로드/작업 메타데이터는 남습니다. 날짜 이동·연체·승급 상한 등은 백엔드의 제어 가능한 Clock 테스트로 확인합니다.

Playwright는 실제 서버와 통신해 DEMO 생성·풀이·결과·편집/초기화·삭제를 확인합니다. 브라우저는 프로젝트 내 무시되는 캐시에 설치합니다. `.github/workflows/ci.yml`에는 PostgreSQL 17 서비스 기반 검증 단계도 포함되어 있습니다. CI 구성의 존재는 해당 실행이 통과했다는 뜻이 아닙니다.

초기 구현의 로컬 확인 결과: 백엔드 **42개**, 프런트엔드 **15개**, 실제 Chromium E2E **2개**가 통과했고 프런트엔드 타입 검사·프로덕션 빌드, HTTP smoke 및 H2 파일 DB 재시작 유지도 확인했습니다. 다중 탭 최초 학습자 발급과 삭제된 퀴즈 문제 복구를 회귀 검사에 포함했습니다. **이 환경에는 Docker/PostgreSQL 실행 도구가 없어 Compose 이미지 빌드·실행 및 실제 PostgreSQL/Flyway 적용은 확인하지 못했습니다.** H2에서의 마이그레이션 성공과 실제 PostgreSQL 성공을 동일시하지 않습니다. Claude는 localhost 모의 HTTP 서버로 계약·실패 경로만 검사했으며 실제 호출은 하지 않았습니다.

## 범위와 배포 한계

회원가입·소셜 로그인·튜터/채팅·코드 실행·관리자·소셜·OCR·이미지/표 이해·스트리밍·SM-2는 제외했습니다. 표와 그림의 의미는 추출하지 않으므로 그런 자료에는 사용하지 마세요. 고정 태그는 서버의 seed/migration에서 수업에 맞게 관리할 수 있으며 모델이 임의 태그를 만들 수 없습니다.

익명 토큰은 **권한을 가진 비밀 capability**이지 본인 인증이 아닙니다. 브라우저 저장소를 지우면 학습자 접근을 잃으며 계정 복구/기기 간 동기화가 없습니다. 토큰을 공유하지 마세요. 학생별 브라우저 프로필을 분리하세요. 공개 배포 전에는 HTTPS, 실제 인증/복구, 사용자·IP별 요청 제한, 업로드 보관/삭제 정책, 예산 한도, 운영 모니터링과 백업이 필요합니다. 현재는 신뢰할 수 있는 소규모 로컬 시험 운영용 단일 서버이며 다중 인스턴스 작업 분산을 지원하지 않습니다.

여러 탭의 첫 접속은 Web Locks로 학습자 발급을 직렬화합니다. 최신 브라우저의 localhost 또는 HTTPS 환경을 사용하세요. 필요한 브라우저 기능이 없으면 조용히 다른 학습자로 바꾸지 않고 오류를 표시합니다.

## 12주 계획과 평가 목표

| 기간 | 산출물 |
|---|---|
| 1–4주 | 웹 MVP: 업로드·생성·퀴즈·개념 오답·Leitner 복습, 데모와 자동 테스트 |
| 5–8주 | 실제 강의 자료/태그 검토, 문항 평가, 오류·재시도·성능·비용 측정, 접근성·배포 신뢰성 개선 |
| 9–12주 | **3명 이상이 2주 이상** 사용, 사용 기록/설문·복습 결과 분석, 한계·시연·최종 발표 |

아래 수치는 **평가 목표이며 달성 결과가 아닙니다**.

| 지표 | 목표와 측정 방식 |
|---|---|
| 사용 가능한 객관식 문항 | ≥60%, 사람 검토로 정확성·명확성·정답 유일성 판정 |
| 개념 태그 일치 | ≥80%, 합의된 수업 태그/사람 라벨과 비교 |
| 파싱 성공 | ≥95%, 최초 응답과 재시도 후 최종 성공률을 별도 보고 |
| 40페이지 파이프라인 | ≤60초, PDF 특성·모델·청크 수·동시성·측정 환경을 함께 기록 |
| 비용 | 제공되는 입력/출력 토큰 사용량과 **측정 당시 모델 가격**으로 산출, 재시도 포함 |

수업 자료와 평가표가 확정되기 전에는 위 지표나 학습 효과를 검증했다고 주장하지 않습니다.
